## 2. The daily timeline
- **4:15 AM ET — scheduled task "DTP morning card kickoff"** (Claude scheduled task, not GitHub cron) first exports the Availability Tracker (`jobs/tracker_export.py` → `data/tracker/player_status.csv`), then pushes it with `triggers/card.txt`. The **Daily card** workflow then: builds the slate if missing (`jobs/slate.py`, ESPN scoreboard) → rebuilds ratings (`jobs/ratings.py`, CBBD box scores) → **scoreboard check** (`jobs/scoreboard.py`, §3; doesn't touch the card) → **player sync** (`jobs/sync_overrides.py`) → pulls lines (Odds API) → writes `cards/card_<date>.csv/.xlsx` → emails Jon (lands ~4:17). GitHub's own crons in `card.yml` still exist but fire 7+ hours late; ignore them (they skip if the card exists). A session that starts after midnight but before 4:15 should wait for this run rather than assume it failed.
  - **Player sync:** an override whose player logged minutes since its `since` date is expired (box score controls, Jon Nov 10); one the tracker marks playing / elig_tro / coach is expired. It flags: tracker notes contradicted by box scores; new unpriced out-statuses (tracker edit within 2 days) for today's teams; and date-expired overrides the tracker still has out — those expired in the last 3 days, or **any time if the team plays today** (Nov 11, after the Grahovac miss). Hidden tracker notes are ignored. The summary leads the card email and is saved as `data/tracker/sync_<date>.txt`. Pricing stays Jon's call — the sync never adds or re-values an override. New overrides need a `since` (the sync fills it with the card date if blank). **Known false flag:** a note edited on game day before tip, for a player who then played, still reads "unpriced" the next day (the sync counts only games after the note's date) — van der Knaap, Nov 12.
- **Right after each Daily card run (chained on GitHub):** **Rotation depth** (`jobs/rotation.py`) and **Tempo tracker** (`jobs/tempo.py`) re-pull the last stored day through yesterday from CBBD play-by-play (date feed, then `/plays/game` for the games the date feed skipped — it returns about half of a day's games). **Totals shadow** (`jobs/kenpom.py` + `jobs/totals.py`) chains off Tempo tracker and builds today's shadow log once (KenPom ratings + FanMatch pulled then; early total = the 4:15 AM card's consensus, locked the first time a game is logged). **Grade** (`jobs/grade.py`) pulls ESPN finals for yesterday, grades yesterday's card against CBBD's closing spreads (§3) and **reruns the scoreboard check with the new closes**. **Role events** (`jobs/role_events.py` + `jobs/roles.py`, workflow `roles.yml`) chains off Rotation depth: pulls yesterday's player shot/assist/rebound events and rebuilds the role cards (`data/roles/roles_current.csv`, `assist_pairs.csv`; §3). Later card reruns trigger the same chain as no-ops. None of these are on the card.
- **Morning (Jon sends to movers from 9 AM; bets ~9–11 AM):** on request, game-by-game reads, sweeps (fresh lines vs the card) and injury pricing (overrides). Extra-board lines (small-conference games) post around 8–9:30 AM; the card has no 4 AM number for them, so moves are measured from the first number Jon logs.
- **Before each tip window (~3:45, 6:45, 9:45 PM on Saturdays):** pull a line snapshot (`triggers/pull_lines.txt`) so every game has a near-close number to grade against.
- **Evening:** Jon usually wants an **early sheet** for tomorrow (§3). Don't push `triggers/card.txt` in the evening — tonight's results wouldn't be in the ratings, and an evening card blocks nothing but is replaced at 4:15 anyway; build the sheet locally instead.

## 3. Routine jobs — how to
**Run / re-send a card for date D:** write `--date D <utc timestamp>` to `triggers/card.txt`, commit, push; watch `gh run list -R jfendler31/DTP-model -w "Daily card"`; log shows `cards/card_D.csv: N games, M with lines` and `emailed`. Re-running overwrites and re-emails. An early (pre-4:15) card is replaced by the 4:15 run, which is the number games are graded against.

**Evening early sheet for tomorrow (Nov 9, Nov 10, Nov 11 nights):** (1) `triggers/slate.txt` = `--date D` (tomorrow) → workflow builds `data/slate_D.csv` from ESPN; the 4:15 run then uses this committed slate (it won't rebuild it, so a game ESPN adds overnight would be missing). (2) Pull lines (`triggers/pull_lines.txt` = a timestamp; if the run sits queued, cancel it and dispatch the workflow with `gh api -X POST repos/jfendler31/DTP-model/actions/workflows/pull_lines.yml/dispatches -f ref=main`). (3) Locally: `python3 jobs/card.py --snapshot data/lines/lines_<latest>.csv --date D --no-email`, copy the xlsx to a scratch folder as `Betting_Sheet_MM-DD_early_<time>.xlsx`, **delete the local `cards/card_D.*`** (never commit them) and send the xlsx. Ratings in it are through the last stored night, so teams playing tonight move at 4:15.

**Pull current lines (for a sweep):** write a timestamp to `triggers/pull_lines.txt`, push; new file `data/lines/lines_YYYY-MM-DD_HHMM.csv` (per-book `home_spread`, `home_price`, `total`, `book_updated`; `williamhill_us` = Caesars). Per-book prices matter: a book holding the number at a heavy price (BetRivers −143 on Murray, Nov 7) is shading toward the next number. **Sweep** = run `python3 jobs/card.py --snapshot <that file> --date D --no-email` locally, compare `market_home_spread` with the card's earlier snapshot, then `git checkout cards/` (don't commit a local card). Note: a local rebuild applies the *current* `data/overrides.csv`, so an override written after 4 AM is already in its model number — don't also add it as a J. "Move" is signed toward (+) / away (−) from the model's side. The snapshot is current numbers with each book's last-update time — not tick history. Circa is not in the feed; Jon watches it on his screen. The consensus is the most common number across books; Jon's screen can be a half-point ahead.

**Price an injury / status (override):** overrides are Jon's call — he states the status; Claude values it.
1. Value = EvanMiya BPR roster with vs without the player, `team_value()` from `jobs/absence_sweep.py` (top-8 minutes curve 32/30/28/26/24/19/15/12), using the **latest EvanMiya player export** (repo `data/evanmiya/ratings_2026-27.csv`; project copy `claude/boards/data/ratings_2026-27.csv`; Jon uploads newer files). **From the Nov 10 export the format changed:** in-season exports list only players who have played, add position/role/class/player_id, and drop the `awaiting_decision` / `season_out` / `inelig_now` flags. The working file merges the new export with the Oct 20 rows for everyone missing from it (`bpr_source` says which), so absent players can still be valued at their last BPR — **check for respelled duplicates** (five dropped Nov 11: Conner/Connor, Samuel/Sam Simmons Jr., Trevon/Tre Blassingame, Steven/Seven Spurlock, Charles/Charlie Dimmock). Raw exports: `data/evanmiya/player_ratings_<date>_raw.csv`. If the team already has players out, value the new one on top of them (cascade). A player missing from EvanMiya's file: use his Torvik rating as a stand-in BPR and say so. A player outside his team's top 8 by BPR is worth ~0 (Jenkins, WVU, Nov 12).
2. Convert: spread pts = value / 10.35 × 9.5; `delta_pts` (the column the card uses, prior/AdjEM scale) = value / 10.35 × SD(prior_pts) ≈ value × 1.22.
3. **Priced share — check it every time (Nov 7 lesson).** If KenPom/EvanMiya/Torvik already removed the player, apply only the unpriced share (weights 45 EM / 35 KP / 20 TV).
   - **Torvik:** `claude/torvik/torvik_fragility_players_all_2026-10-23.csv` — in the projected top 10 with minutes = counts him.
   - **EvanMiya:** the team-rating test: regress EvanMiya team `bpr` (from `data/prior_2026-27.csv`) on each team's `team_value()` from the Oct 20 player file across all teams (n≈340, slope ≈1.16, residual SD ≈1.55); if the team's actual EM rating sits nearer the *without-player* prediction, EM has removed him. Nov 7: counts Haynes, Anderson, Welling; appears to have removed Padjen and Skillings. Nov 8: counts Washington (Boise St.), Steger (Siena), Hawaii's Joses/Dan/Kerr; appears to have removed USC's Collins + Reibe. Can't separate absences under ~1 per 100 — then use timing. In-season exports can't run this test.
   - **KenPom:** no player-level view; treat as unknown unless there's evidence.
   - When unknown, say so and use full value unless Jon says otherwise.
   - **In-season overlap (Nov 9).** Once a team has played D-I games without the player, its in-season data already carries part of the absence: J = value × (1 − λ × share of the team's D-I games he missed), λ = N/(N+K). **The reverse also applies:** a player who missed an in-season game and is back means the model underrates the team by λ × value × share.
4. Append to `data/overrides.csv`: `team` (KenPom spelling), `player`, `status` (out / doubtful / limited / venue …), `delta_pts`, `expires` (`until cleared`, `season`, or a date — the card skips rows whose date is before the card date), `reason` (source + assumption), `since`. Commit, push. **One-game calls (GTDs, "likely out", "confirmed out" without a timeline) get that day's date as expiry.** For a player whose return the box score will show, `until cleared` is fine — the sync retires it when he logs minutes (Collins, Dort, Nov 11).
5. Update the tracker note only if something on it needs changing; never set `added`.
6. Tell Jon the spread effect and the **J value for his sheet**. **J is home-spread points: the sheet computes edge = market − (model + J), so a home-team absence is positive and an away-team absence negative.** If the override is written before the card he'll use, it's already in the model column; don't give it as a J too.

**Venue (neutral-site crowd) calls:** Jon's judgment, written as a one-game override row with status `venue`, delta_pts = spread × SD/9.5 (≈ spread × 1.33). Reference points: Saint Louis at Enterprise Center (split crowd) +0.5; **SDSU at Pechanga Arena +2.0** (Nov 7); Providence at Mohegan Sun discussed at 2.0–2.5, not written; Rhode Island at Mohegan Sun ~1.0–1.5 (not written); Virginia vs Arkansas in DC (KenPom "Semi-Home", ~2 for UVA, not written); Penn St. vs Pitt at the Palestra (~0.5 PSU, not written); UT Arlington at Hawaii after several days on the island (take ~0.3–0.5 off Hawaii's 2.6). Rule of thumb: a near-home neutral crowd ≈ half to two-thirds of the team's KenPom HCA.

**Grading finished games — automatic.** Workflow **Grade** (`jobs/grade.py`) runs after every Daily card run and grades yesterday: reference = the card's 4 AM number (CBBD opening spread for extra-board games the card had no line for), close = CBBD closing spread (median across books), model side from the card's size-adjusted model as built that day; ATS vs the reference and vs the close, and CLV (+ = market moved toward the model), by edge band. Output `data/grades/grade_<D>.csv` and a season log `data/grades/grade_log.csv`. Regrade or backfill: `triggers/grade.txt` = `--date D` or `--start A --end B`. **Bad reference in the log:** Nov 2 Merrimack at Appalachian St. (ref App St −8.5 vs close +3.25); drop rows with |ref − close| ≥ 6 when summarizing. Season through Nov 11 (461 games, bad refs dropped): CLV +0.14; <1 −0.13, 1–2 −0.14, 2–3 +0.58, 3+ +0.84; 3+ ATS vs the close 24-39.

**Calibration report (weekly on Mondays, and on request) — `python3 data/research/calibration/calibration_report.py [--start D] [--end D]`** (reads `data/grades/grade_log.csv`, drops rows with |ref − close| ≥ 6 and names them). What we want (Jon, Nov 9): **CLV rising with edge size, and roughly in proportion** — the capture rate (CLV ÷ average edge) about the same in every band. CLV that rises but less than proportionally means the model overstates its biggest edges; flat or falling CLV means the edge ranking carries no information. Read three cuts:
- **By 4 AM edge band** (the headline).
- **Model on the favorite vs the dog.** In November the market bids up favorites all day, so favorite sides earn CLV at every band without any model information. **The dog-side rows are the cleaner test.**
- **Line 15+ vs under 15** (where the size curve and the opening-week drift live).
Results (ATS by band) lag CLV; flag a band only when both disagree for weeks, not days.

Baseline, Nov 2–8 (324 games, App St Nov 2 dropped):

**Grading by hand (same-day checks).**

**Scoreboard check (Nov 11) — `data/ratings/scoreboard_<date>.csv`** (`jobs/scoreboard.py`; runs in the card job and again in Grade; `python3 jobs/scoreboard.py` locally). One row per team: `games` with a close, `raw_vs_close` (margin + the team's closing spread, summed), `luck_3p` (3 × (3PM − D-I 3P% × 3PA), side minus opponent), `luck_ft_own` and `luck_ft_opp` (each side's FTM minus its FT talent × FTA; opp shown with the team's sign), `adj_vs_close` = raw − 3P luck − FT luck, `adj_per_game`, `scoreboard_move` = λ × adj per game (the rating move the scoreboard alone implies), `composite_move` (the in-season part of the rating), `gap`, `ft_talent`, `ft_proj`. **FT talent** = player-based projection (each player's prior-season FT% shrunk toward D-I with 40 pseudo-attempts, weighted by his FTA this season; new D-I players 0.706; +0.9 pt year-over-year) blended with the team's observed FT% at FTA/(FTA+220). Projection r 0.43 with a team's final FT% (team FT% a year earlier: 0.24). Use it before trusting an in-season-driven edge: when `gap` is large, ask whether the composite or the scoreboard is closer to the truth (garbage time flatters blowout losers on the scoreboard — side with the composite there). Diagnostic only; nothing in the card reads it. **From Nov 13 (added Nov 12):** `sb_move_adj` = the opponent-adjusted scoreboard move vs our prior (same rating machinery as the composite, one luck-adjusted net-points pillar; covers teams with no graded close too), `blend_move` = 0.7 × composite + 0.3 × sb_move_adj, `blend_delta` = blend − composite (points to add to a team's rating). **Reads use `sb_move_adj` / `blend_move`**, not `scoreboard_move` (which is vs the closes). FT talent uses the player box files on hand, so it lags a day unless yesterday's box has been pulled.

## 4. How the ratings work (decisions in force)
- **Prior (frozen Nov 2):** `z_prior` = EvanMiya 45 / KenPom 35 / Torvik 20 (z-scored), + 0.3 × H.U.M.A.N. poll residual (tapered).
- **In-season (`jobs/ratings.py` / `jobs/ratings_core.py`, nightly in the card job):** four-factor composite (net 2PT% .32, OREB rate .26, TO rate .24, 3PT% .10, FTA rate .08 — **FT *rate*, not FT%**), opponent/home-adjusted ridge SRS; final margin is not an input. **Garbage time out (live from the Nov 9 card):** possessions leverage-weighted from play-by-play, overtime kept, each game weighted by its competitive possessions. Blend λ = N/(N+K), N = D-I games, **K = 8 through Nov 30 → ramp to 12 by Jan 15**. Games against non-D-I opponents don't count.
- **Games 1–2 (early method), opponent-current from the Nov 12 card (Jon, Nov 11; `OPP_CURRENT = True` in `ratings_core.py`):** a team with <3 D-I games moves by λ × its four-factor surprise, where expectation = home + gap between the two teams, and **the opponent is rated at its current rating (its own early move, leave-one-out of this game) rather than its preseason prior.** Fit: composite = 0.084·home + 0.332·gap; surprise ÷ the gap coefficient is in rating units. On Nov 11, 198 teams moved, 3 by 0.5+ (max 0.63). Big expected blowouts move least. From game 3, the SRS blend. **Backtested Nov 12 (two seasons): neutral** — MAE 9.329 vs 9.330, ATS 3+ vs close 54.2% vs 54.1%, CLV identical; kept.
- **Not re-standardized:** a team with no games stays at its prior.
- **Spread:** −(9.5 × (z_home − z_away) + KenPom HCA[home]); neutral 0. Ratings are per game (≈ 0.745 × KenPom AdjEM), not matchup-pace-adjusted.
- **Size curve (card only):** model spread widened **0.20 pt per point beyond 10**, **only in non-conference games where the model favorite is at home** (`curve_ok()` in `jobs/card.py`; `size_curve` column). Fit on week-one buy games; provisional until the two-season sweep (with opponent tier). Don't count "the curve says X" and "week-one tier says X" as two signals.
- **Where the four factors and KenPom diverge:** our model discounts threes (weight .10) on purpose; a cover built on threes moves KenPom up and us little. **Nov 12 test (`Composite_vs_KenPom_Test_2026-11-12.md`, two seasons, KenPom archive snapshots):** from the same preseason start, our in-season update beat KenPom's on margin (MAE 9.32 vs 9.44) and against the close (3+ edges 54.4% vs 48.9%, both seasons); the part of our move KenPom's move doesn't share is worth +0.65/pt vs KenPom's number, and KenPom's own Nov–Dec moves overshoot (−0.28/pt). **Treat "KenPom today" as ~0 weight in Nov–Dec reads — not independent support, and not a reason to shrink when it disagrees.** KenPom's preseason stays in the prior as before.

## 5. Things we've learned (read before calling a game)
- **Opening-week drift:** 20+ (and 15+) home favorites get bet up ~1 pt between 4 AM and ~1 PM; they covered the close 57.5% / 52.7% in the backtest seasons. Big-dog edges grow through the morning for that reason, not because they got better.
- **Afternoon buyback (hypothesis):** 20+ home favorites run up in the 10 AM pulse partly come back by early afternoon (Nov 9: +0.9 to the peak, −0.4 by 2:51 across 18 games). Test: 4 AM / ~10:30 peak / ~2 PM / close for every 20+ home favorite.
- **Stay-away rule — what the evidence actually is.** The backtest finding (`Intraday_Line_Movement_2025-26.md`) is narrow: **model edges of 3+ at 6 AM where the line moved 0.5–1 pt away by 11 AM → model side 39–40% ATS**; one season, old model, n ≈100. No tested 1.5+ bucket. It does **not** cover edges the move itself created — those are mostly the market being right. Cite it at this strength.
- **Buyback the model supports:** steam that crosses the model number shows as "toward" but flips the edge.
- **Week one by tier (Nov 2–6):** 15–20 favorites covered 27-12-1; 20+ a coin flip; under 15 the model side went 57-42-3; 3+ edges 13-18-1.
- **Post-hoc explanations (Nov 7 lesson about Claude's reads).** (1) pre-tip reads in fixed terms; (2) graded in bulk on CLV and record by edge band; (3) post-game reads use four factors vs expectation only; (4) game-by-game commentary is discounted until the log has weeks in it; (5) no "right pass" claims from one result.
- **Fixed tag list for reads:** placeholder rating; **single-system edge**; **in-season-driven edge, market at priors** (a new coach makes the prior *less* reliable, which argues for weighting the games more); unpriced travel/B2B; move-created edge; big-dog tier. **System check:** each system's number with J applied (EvanMiya and Torvik priors on our scale, KenPom preseason and today), support when ≥0.5 past the line on the model's side.
- **Candidate triggers (untested):** one site pricing a placeholder roster; prior-only team missing a projected top-5 player in a non-D-I opener; edge against one system only; market past every system.
- **Back-to-backs / next-day travel:** not in the model; Jon priced Oakland's overnight turnaround at 1.5–2.5. Jon gives schedule fatigue less weight than the market does.
- **New-coach / zero-continuity teams:** KenPom continuity counts only minutes returning at the same school, so a coach who brings players with him reads as 0%. The Nov 9 replay found signal only at 0% continuity (11 of 15 moved with the close); apply year-zero weighting at about half.
- **Continuity, more broadly (Nov 11, `Cumulative_Continuity_Test_2026-11-11.md`):** KenPom's preseason **over-rewards continuity** everywhere (≈2.3 pts of preseason→Jan 3 move per full point of continuity, ~3 SE). Patriot/Ivy teams losing several multi-year starters did **not** run below preseason (2022–2026, n=90; if anything above). A small cumulative-loss effect exists in portal leagues (−0.09 per starter-season lost). **No extra haircut for low-portal teams with big multi-year losses** (Navy 2026-27).
- **Garbage time (Nov 8):** ~18% of D-I possessions are low-leverage. The raw scoreboard flatters blowout losers (Milwaukee, UIW, Mississippi Valley, Bethune-Cookman) — side with the composite there.
- **Three-point variance (Nov 9).** Per-game three-point swing SD ~11 points — about the whole noise around a spread. In-season 3P% doesn't persist yet, so the .10 weight is right. **Dog tax** hypothesis (model-on-dog −1.7/game with team baselines): test before acting.
- **Free throws (Nov 11).** Own team FT% split-half reliability: ~0.2–0.3 at 3 games, 0.3–0.4 at 5, ~0.45–0.5 at 10, ~0.5 at 13 (Nov–Dec 2024-25 and 2025-26). **Opponent FT% ≈ 0 at every point — pure noise to a defense.** Team FT% year-to-year r 0.22 (KenPom 2014–26); player-based projection 0.41–0.43. True team FT% SD ≈2.9 pts ≈ 0.5 pts/game; FT luck ≈2 pts/game per team (SD), vs ~8 for threes. Removed from the scoreboard check; the composite still uses FT rate (swap to rate × expected FT% is a queued backtest; expected to matter from mid-December, for teams extreme on both FT rate and FT%). First use corrected a read: SDSU's opponents missed ~6 pts of FTs, so SDSU ran ~3.8/game worse than the closes, not even.
- **Pressure × slow offense (Nov 9):** treat turnover matchups as additive (no interaction).
- **Foul-drawers vs foul-prone defenses:** the one player type whose value rises against a specific defense (Tyson, Chaze Harris).
- **Nov 10 lessons (Claude's reads):** (1) **Model on the dog vs a 15+ favorite with a 3+ edge: 7-11 vs the close, CLV +0.06** — shrink those edges hard; dog sides at lines 15–25 went 25-41 vs the 4 AM number through Nov 10. (2) **Neutral sites: 9-19 vs the close over 28 games**, our numbers 0.8 shorter than market. (3) Before trusting an in-season-driven edge, check the scoreboard file. (4) Bench depth (slots 9–10) does not predict big-favorite covers. (5) Torvik play-type pages show zero pull-ups / floaters / post-ups for teams whose games came off feeds without shot descriptors — artifact. (6) KenPom height is from D-I minutes — refresh before use. (7) The card does not scale for tempo. (8) In-state altitude neighbors make the KenPom HCA too big (~0.5–1, untested). (9) Check career 3P% for transfers shooting hot early.
- **Shadow totals (Nov 11):** 100-106 overall; the bias is efficiency (≈+0.022 PPP, ~3 pts low), not pace. The formula averages the four efficiencies, which shrinks lopsided matchups toward the middle, and has no home-court term — its gaps in fast or lopsided games (Cal Poly/GCU) are a blind spot, not information. Keep in the shadows.
- **Composite vs scoreboard (Nov 12, `Composite_vs_Scoreboard_Test_2026-11-12.md`; repo `data/research/comp_vs_sb/`):** when the two in-season readings disagree, **the truth sits ~30% of the way from the composite toward the luck-adjusted scoreboard** (margin regression 0.74 composite / 0.31 scoreboard; team-level slope −0.29, se 0.11, both seasons; possibly up to ~40% when the composite is well *above* the scoreboard). In reads: in-season credit = composite move − 0.3 × (composite − scoreboard), using the **opponent-adjusted** scoreboard (`sb_move_adj` / `blend_move` in `scoreboard_<date>.csv` from Nov 13; for re-pricing a whole card, `python3 data/research/comp_vs_sb/live_sb.py --date D --w 0.3 --card cards/card_D.csv`) — not the file's `scoreboard_move`, which measures vs the closes. Composite alone still beat the close on 3+ edges both seasons (54.2%); the scoreboard earns more CLV (the market moves toward points) but less ATS. No card change.
- **Injury news the ratings miss** is the biggest single source of bad edges — check the tracker and `data/overrides.csv` for both teams before trusting an edge.
- **Three-point luck is measured against the D-I average (Nov 12, Coppin St.):** for a team that has shot badly for years (Coppin St. 3P% ranked 326th–354th three straight seasons), part of its "bad luck" is talent, so its luck-adjusted scoreboard overstates it. Discount the scoreboard credit for teams at the extremes of multi-year shooting; for a team whose coach has a long good-shooting record (Wardle at Bradley), treat a cold start as mostly luck.
